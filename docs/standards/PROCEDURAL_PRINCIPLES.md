# Procedural Principles

These rules cover generators and their projections.

## 1. Determinism

| ID    | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PD-1  | **Reproduction contract.** An output depends on the generator version, normalized seed, inputs, continuation state and draw order within its streams. Identical values in the declared runtime yield the same data.                                                                                                                                                                                                                                                                                                                                                                                      |
| PD-2  | **Seed.** Integer in `[0, 2³²)`. The entry boundary validates or normalizes it. Normalization lives on the generator.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| PD-3  | **PRNG.** One continuing seeded stream type owns random state and derives keyed child streams. Changing the algorithm or a draw sequence requires a new generator version.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| PD-4  | **Child streams.** Give each generator a stable child key so its result is independent of the order in which other generators run. Derive each child from its parent’s seed and key, independent of the parent’s current draw position. Use the same mechanism for separate purposes such as structure, decor and analysis.                                                                                                                                                                                                                                                                              |
| PD-6  | **Draw sequence.** Number and order of draws per operation are part of the contract. View, color, focus, metrics, saving, and rendering do not draw from domain streams and do not mutate structure.                                                                                                                                                                                                                                                                                                                                                                                                     |
| PD-7  | **Ordering and tie-breaking.** The order in which an operation reads, iterates, decides, and emits is a documented contract and stays preserved ([C-50](CODING_STANDARDS.md#refactoring)). Ordered inputs such as polygon rings, program stacks, and draw sequences are never re-sorted. Canonicalization, e.g., by stable ID, happens only for what the contract explicitly declares unordered (sets, candidate lists); there, the stable ID also breaks ties. No decision depends on an undocumented Map, Set, or key iteration order.                                                                 |
| PD-8  | **Continuation.** Complete continuation captures a declared state inventory: domain state, cursors (step, budget, and path progress; clocks where present), RNG state per stream, and explicit rebinding of matching procedures. Seed or partial capture alone does not continue anything. Sign-off is separate from round-trip: continued run against uninterrupted run, with the named inventory. A snapshot or codec (`encode`) alone does not guarantee continuation; it can carry it if it captures the full inventory and passes the comparison test. Without that proof, nothing is a checkpoint. |
| PD-9  | **Runtimes.** Only the declared runtime is guaranteed. Bit-exactness across Bun, Chromium, Workers, or GPUs is claimed only after proof. Results of `Math.sin`, `exp`, and relatives never branch decisions.                                                                                                                                                                                                                                                                                                                                                                                             |
| PD-10 | **Incremental = full rebuild.** A local update produces the same authoritative state as rebuilding from the same intent. Otherwise, the repair history is persisted alongside it.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| PD-11 | **Version.** Saved and frozen outputs state format version and generator version. Any rule change that changes outputs increments the version.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| PD-12 | **Work budgets** count steps, not milliseconds. Termination states are declared.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## 2. Units and Coordinate Systems

Keep these five coordinate spaces distinct.

| Space    | Coordinates                                                                             | Unit          | Owner                        |
| -------- | --------------------------------------------------------------------------------------- | ------------- | ---------------------------- |
| Carrier  | `(quad, u, v, level)` with `u, v ∈ [0, 1]`                                              | dimensionless | Topology in headless modules |
| Grid     | Indices or IDs of a grid generator                                                      | integer       | respective generator only    |
| World    | `x, y` ground plane; `z` height; right-handed; rotation around `z` positive CCW in plan | m, rad        | headless modules             |
| Renderer | three.js: `y` up, right-handed                                                          | m             | `scene/`                     |
| Screen   | CSS pixels; in 2D drawings `1 U = 4 px = 1 m`                                           | px            | UI, `src/app.css`            |

| ID   | Rule                                                                                                                                                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PE-1 | **Units in headless modules:** length in meters, area in m², angle in radians. Degrees only for display and quality angles, then named in the identifier ([NC-30](NAMING_CONVENTIONS.md#units-and-values)). Levels are discrete indices, not heights. |
| PE-2 | **One transition World → three.js:** exactly one named function, `(x, y, z) → (x, z, −y)`. That is a rotation; handedness is preserved. A rotation around world `z` by `+θ` is a rotation around three `y` by `+θ`. No second conversion elsewhere.   |
| PE-3 | **Resolve deviation:** Any other axis mapping in the repo is removed or documented as its own space with declared handedness.                                                                                                                         |
| PE-4 | Camera, section, exploded view, focus, and screen size do not change world coordinates.                                                                                                                                                               |
| PE-5 | Same structure is not same meaning. A world `Vec3` is not a renderer `Vec3`. Transitions between spaces, units, or dimensions go through a named adapter.                                                                                             |
| PE-6 | **Contract probes.** Every transformation has tests with known points and a rotation. Examples: world `(1, 2, 3)` → three `(1, 3, −2)`; carrier corners `(0,0)`, `(1,0)`, `(1,1)`, `(0,1)` → the four quad corners counter-clockwise.                 |
| PE-7 | **Precision.** Authoritative positions are `number` (Float64). Float32 is a projection format in `scene/`. Float32 as a core format requires a documented precision bound and a measurement.                                                          |

## 3. Numerics

| ID    | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PN-1  | **No global magic tolerance.** Every tolerance has a name, unit, reference measure, and operation. It is derived from scale, e.g., area sum `1e-9 · max(1, A)`.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| PN-2  | **Robust predicates.** Topological decisions (orientation, side, intersection yes/no, inside/outside) use a floating-point filter and compute exact signs when uncertain. Constructions (intersection point, area) remain floating-point and are not called exact.                                                                                                                                                                                                                                                                                                                                                            |
| PN-3  | **One predicate, one owner.** Geometric predicates are never copied.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| PN-4  | **Integer decisions.** Whatever must agree across runtimes decides on integers: quantized dimensions (`1 mm`) or integer hash. The quantization contract specifies per quantity: rounding rule including half-way behavior, value range, declared overflow handling (never silent, [PT-10](#4-topology-and-embedding)), and origin of the quantized input (stored authoritatively as integer or derived from Float64). Quanta derived from floats are only as consistent as their inputs. Boundary cases near half a unit and at range limits are compared across declared runtimes. Integers alone do not prove determinism. |
| PN-5  | **Degeneracy is defined per operation.** Every operation declares which degeneracies it rejects, which it supports, and what happens to supported ones; likewise boundary membership (point on edge, interval endpoints). `NaN`, `Infinity`, and zero-length edges are rejected at the boundary with an error code. Collinearity is not a general error: supported collinear boundary vertices are preserved. If an operation requires strict convexity or distinct points, that lives in its contract and produces a declared error code, never silent repair.                                                               |
| PN-6  | **Shared edges** are computed once from an ID in canonical order (sorted endpoint pair). Both neighbors receive bit-identical values.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| PN-7  | **Topology never from rounded coordinates.** Connectivity comes from shared IDs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| PN-8  | **Quality measures are an executable contract:** `J_s`, minimum angle, aspect ratio, area. Bounds are parameters and are never silently relaxed. Failing means error, not repair.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| PN-9  | The corner test `J_s > 0` holds only for planar bilinear quads. For trilinear solids it is no proof; interior samples are spot checks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| PN-10 | **Predicates do not replace domain dimensions.** Minimum frontage, minimum area, and clear width are metric rules and are checked separately.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## 4. Topology and Embedding

| ID    | Rule                                                                                                                                                                                                                                   |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PT-1  | **Carrier and position layer.** Topology, embedding, and representation are separate contracts. Topology = IDs and incidence. Embedding = positions. A grid is a position layer on a carrier; other valences need another carrier.     |
| PT-2  | **Topology contract** names: cell IDs, dimension, neighbors with ordering, boundary handling, weights, mapping to geometry.                                                                                                            |
| PT-3  | **Grid-agnostic.** General algorithms read only the graph: no `i/j` arithmetic, no hidden square offset. Every algorithm names the grids on which it is tested. Quad-specific assumptions live in the contract.                        |
| PT-4  | **IDs** are stable and come from input and rule path, never from coordinates. Identity, index, and label are distinct. Split and merge require explicit mapping.                                                                       |
| PT-5  | **Invariants.** Every operation declares its invariants and preserves them: finite coordinates, simple CCW rings, consistent half-edges (`next`, `prev`, `twin`), at most two faces per edge, provenance tree, area sum, quad quality. |
| PT-6  | Every operation declares what it checks locally and globally, and its cost. Locality is not claimed when a global check is performed.                                                                                                  |
| PT-7  | **Transaction:** proposal → dependency closure → validation → commit. Atomic: if validation fails, the predecessor remains unchanged. A no-op returns the previous state. Shared, untouched structures are declared.                   |
| PT-8  | `readonly` is not deep protection. The contract states whether an output is detached, a reference snapshot, or a live view ([C-23](CODING_STANDARDS.md#types-and-contracts)).                                                          |
| PT-9  | **Undo/Redo** returns the exact saved states. Foreign or stale histories are rejected.                                                                                                                                                 |
| PT-10 | **Errors are results:** declared codes such as `quality-unattainable`, `landlocked`, `protected`. No silent repair, no silently lost area. Whether exception or result type is specified in the contract.                              |
| PT-11 | **Continuous and discrete separated.** Continuous: positions, heights, split ratios. Discrete: topology, occupancy. In the continuous regime no ID and no topology changes.                                                            |
| PT-12 | **Morph only within verified bounds:** `J_s`, step size, metric minimum frontage. Outside them follows a declared event with hysteresis, no silent re-identification. Interpolation does not make an invalid target valid.             |
| PT-13 | **Carrier coordinates preserve identity, not meter dimensions.** After every position-layer change, access and dimension rules are re-checked in meters.                                                                               |
| PT-14 | **Caches** have owner, key, and invalidation. No cache outlives the topology it represents. Caches are instance-bound.                                                                                                                 |

## 5. Projection

| ID   | Rule                                                                                                                                                        |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PP-1 | **Rendering is projection:** `intent → validated state → derived geometry → view`. Data describes geometry and material headlessly; `scene/` translates.    |
| PP-2 | **Nothing flows back.** Topology and domain state are never computed from meshes. Selection reports ID and action. A mesh mutation is not a state mutation. |
| PP-3 | Frame rate, resize, and camera change no domain rule and consume no draws. Transitions are view state.                                                      |
| PP-4 | **View changes** (color, focus, section, exploded view) regenerate no structure and upload no geometry.                                                     |
| PP-5 | **One data source.** Bible demos and the sandbox read the same data.                                                                                        |

See [Architecture](ARCHITECTURE.md#rules) for the stage and [Design Standards](DESIGN_STANDARDS.md#color-and-material) for color and material.

## 6. Budgets and Measurement Duty

| ID   | Rule                                                                                                                                                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PB-1 | A budget names a number, unit, scene, test method and tier (Must, Should, Could).                                                                                                                                                          |
| PB-2 | **Measurement duty.** No claim on performance, memory, or quality without measurement. "Satisfied by construction" is not a measurement.                                                                                                   |
| PB-3 | Record the device, OS, runtime version, scene size, seeds, warmup and measured runs, statistics including p95 definition, timer limits, memory method and interference. The default is two warmup runs, five measured runs and the median. |
| PB-4 | "Passed" holds only for the stated test domain. Partial timings are not added into a city total.                                                                                                                                           |
| PB-5 | **Blocked remains open.** Missing GPU or browser evidence is not replaced by reading source code or using a software renderer.                                                                                                             |
| PB-6 | Stopping criteria are fixed before measurement. Rejected hypotheses remain documented. No rescue variant inside the same series, no cherry-picking the best seed.                                                                          |
| PB-7 | **Subjective criteria** are decided by the author alone, with date. Metrics do not replace judgment.                                                                                                                                       |
| PB-8 | **Regression protection:** frozen hashes, metric tables, comparison plates. Frozen expectations change only by documented author decision ([C-43](CODING_STANDARDS.md#reference-code)).                                                    |
| PB-9 | Optimize after measurement.                                                                                                                                                                                                                |
